## 反省 1: 「変更前から穴だった」を「その穴に新しいものを落とさない」と読み替えた

D3 敵対レビューは P2-7 で「caller の分岐は docker stub が payload を実行しないので未検査」と
指摘した。私は**「変更前から同じく未検査で、今回の変更が作った退行ではない」**と判断して
静的 pin だけに留めた。判断自体は事実として正しい。

しかし**その直後の CI run が、まさにその盲点の中で exit 127 を出した**
(reference 側の古い worktree に新設 script が無い)。既存の穴は「新しいものが落ちない安全地帯」
ではなく、**新しく足したものが最初に落ちる場所**だった。

- 正しい問いは「これは私が作った退行か」ではなく **「私が今足すものは、この穴の中を通るか」**。
  通るなら、穴が既存かどうかに関係なく、そこを見る手段が要る。
- **切り出し先案**: `adversarial-review-own-safeguards.md` へ追記
  (「既存の未検査領域を理由に指摘を先送りするとき、**自分の変更がその領域を通るか**を先に見る」)。
  発動点は既存ルールの §7「指摘を直した差分にもう 1 周」と同じ敵対レビュー後なので、新規は立てない。

## 反省 2: 既に完全一致 pin が在ったのに、自分で弱い近似の pin を新設した

私が足した配線 pin は `run-resource-performance` を **grep して文字列の存在**を見ていた。
一方 harness には `expect_resource_performance_docker_argv` があり、docker の argv を
**完全一致で diff** している。payload 本文は argv に含まれるので、**既存 pin の期待値を更新するだけで
反省 1 の退行は commit 前に落ちていた**。

これは `adversarial-review-own-safeguards.md` §0-B「その答えを既に出している経路はないか」の
**検査を新設するとき版**。私は 0-B を読んでいたが、発動点を「守り (allowlist / 突合) を足すとき」と
理解していて、「**テストの pin を足すとき**」に適用しなかった。

- **切り出し先案**: `adversarial-review-own-safeguards.md` §0-B に「pin / 検査を足すときも同じ」の
  1 行を足す。新規ルールは立てない。

## 反省 3: 観測点を副作用の「前」に置いて、回数を数え損ねた

purge の回数を数えるために stderr の 1 行を機械可読な観測点にしたが、その行を `rm -rf` の
**前**に出していた。そのため「1 回目だけ purge する」変異 (M6) を当てても行数は 3 のままで、
**意図の回数を数えて実行の回数を数えていなかった**。観測点を `rm` の後ろへ移して初めて red になった。

- **切り出し先案**: `mutation-verify-new-tests.md` の「その assert が見ている量は、壊れたときに
  動くのか」に **「観測点は副作用の後に置く (前に置くと意図を数える)」** を 1 行追記。

## 反省 4: 自分の計測で `$?` を壊した

ガードの rc を測るとき `echo "... $(basename $sh) rc=$?"` と書き、**コマンド置換が `$?` を
上書き**して全ケース rc=0 に見えた。「拒否が効いていない」と一瞬誤診した。

- **切り出し先案**: `measure-external-cli-streams-separately.md` に
  「**rc は同じ行のコマンド置換で壊れる。先に変数へ退避してから使う**」を 1 行追記。
  同ルールの「stdout/stderr/rc を分けて採る」の直下が適切。

## 反省 5: 変異が的を外していたのを「テストの穴」と誤読しかけた

ガード規則 g の変異で、3 項の論理和の**第 1 項しか無効化していなかった**ため残り 2 項が拾い、
GREEN を「テストの穴」と読みかけた。diff を読んで変異を直したら red になった。

これは `mutation-verify-new-tests.md` の手順 1.6 (変異の diff を目視する) が既に警告している形で、
**ルールを読んでいたのに踏んだ**。新規ルールは不要で、rationale 側に実例を足す価値はある。

- **切り出し先案**: `rules-rationale/mutation-verify-new-tests.md` に実例として追記 (本文は変えない)。

## 反省 6: bash 3.2 で安全機構がクラッシュしていた (codex 実装の検閲で発見)

codex の初版は空配列を `set -u` 下で展開しており、macOS の `/bin/bash` (3.2) では
`SWIFTPM_ARTIFACTS_DIR=/` が拒否 (rc=2) ではなく `unbound variable` (rc=1) になっていた。
CI は Linux bash 5 なので**緑のまま見えない**。

`mutation-verify-new-tests.md` の「手元 1 platform の緑は『その platform では壊せなかった』
でしかない」の実例そのもの。ルールは既にあるので**追記不要**。字句 pin で再発を止めた
(pin 自身も変異検証済み、かつ自分のコメントに反応しない形へ直した)。
