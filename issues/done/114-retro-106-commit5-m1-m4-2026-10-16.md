# 114 (retro): issue 106 Commit 5（M1〜M4）の性能の退行への対処、x86 の切り離し、codex が止まったときの引き継ぎの振り返り

起票日: 2026-10-16

経緯と数字は `done/106` の「Commit 5」節、issue 112（x86 の切り離し）、issue 113（arm64 の crash）にある。ここには、踏んだことと次に効く改善だけを書く。

## どこで踏んだか

1. **CI の runner を x86 から arm64 に移した直後、性能の gate が黙って skip された。** arm64 の kernel は `/proc/cpuinfo` に `model name` を出さず、
   cpu_model が `unknown` になって比較が拒まれ、`--fail-on-regression` でも「Regression gate skipped.」で exit 0 だった。CI は success のままで、
   `verify-agent-push` の再現で初めて気づいた（`bin/ci/cpu-model` を足して直した。issue 112）。runner を替えた commit で、gate の出力の中身（比べたか・skip か）を読んでいなかった。
2. **性能の改善を、gate と違う CPU アーキテクチャの数字で判断した。** M1+M2 の退行を arm64 の手元で −11.5% まで縮めたが、x86 の CI では −14.7% のままだった。
   既存ルール（`perf-claims-need-measurement.md` の「gate と同じ OS・CPU で比較してから採用」）どおりの形で、規則の欠落ではない。最後は x86 を外して arm64 で測る形に変えた。
3. **slot table の効果の見積もりが大きく外れた。** 実装の前に「0.3〜0.8M Ir 減」と見積もったが、実測は約 79k Ir（退行の約 1%）で、悪化して戻した。
   次に選んだ「正常系の遷移をまとめる」は、記録済みのコストの分類（遷移ごとの exclusivity check・ARC・enum）に沿った案だったが、約 0.5M Ir（約 1 割）にとどまった。
   遷移の重さそのものは、単一の遷移関数と canonical な record を保つ限り大きくは減らないと分かり、最後は x86 を外す判断になった（局所の経緯。一般化できる改善は無い）。
4. **実装者の検証の報告に穴があった。** M4 では、codex の「重複 ack を二重に減らす変異で red（−2）」が本物の検出ではなかった（hook が CREATE で止まり、ack が 0 件のまま何もしない dispatch を数えていた）。
   M3 では、ユーザーが承認した通常の経路の待ちにテストが無かった（変異で消しても 873 件が緑）。どちらもレビュアーが見つけ、main agent が変異を当て直して確かめた。
5. **SwiftLint analyzer（unused_declaration）を手元で回さずに push し、CI で落ちた。** 実装者は「関数を消していない」として回さず、main agent も strict lint だけで代用した。
   関数の宣言は残ったまま、レビュー対応でその参照だけが消えて未使用になった。repo の CLAUDE.md の書き方（「関数・型・import を置き換えたり消したりしたら」）が、参照を消した場合を拾わない。
6. **issue の commit を続けて push し、直前の commit の Issues の run が取り消されて `verify-agent-push` が rc=1 になった。** 既存ルール（取り消された run はその commit を検証していない）どおりで、最後の commit で検証し直した。
7. **codex が 5h の枠で実装の途中で止まった。** 差分（+1066 行）が残っていたので、同じ指示文で Claude のサブエージェントに続きを頼み、完走した（ユーザー指示。memory に保存した）。
   引き継いだサブエージェントは、codex が入れた設計外の機構（期限の無い待ち）を見つけて撤去した。

## 次に効きそうな改善（一般形）

- A. 却下: 「CI の runner・OS を替えたら、検査が走って比べたかを出力の中身で確かめる」は、既存ルール `verify-execution-not-just-exit-code.md` の
  「実行環境を変えたら、変更前後の出力を全行 diff する」（「中で skip に化ける」まで書いてある）で足りる。今回は守らなかった（不履行）
- B. 却下（一般ルール）: 「未使用の検査を参照を消したときも回す」は、既存ルール `verify-execution-not-just-exit-code.md` の「最後の編集の後に CI と同じ lint・テストを回し、別の検査で代用しない」で足りる。
  局所の改善として、swift-smbee の CLAUDE.md の lint-analyze の条件に「参照を消して宣言が未使用になったとき」を足した（この retro と同じ commit）
- C. 却下: 「プロファイラの上位を分類してから案を選ぶ」は、今回は分類を記録したうえで案を選んでいたので、この経緯からは根拠にならない（見積もりが外れただけ）
- D. 却下: 「実装者の変異の報告を当て直す」は既存ルール（`subagent-model-tiering.md` の検閲、`mutation-verify-new-tests.md` の「最初に落ちる assert を予測し一致を確かめる」）で足りる。今回は守って見つけた
- E. 却下（局所）: `bin/ci/verify-agent-performance` が push の run しか見ず、`reference_sha` で手動起動した候補の run を検証できない。この repo の道具の改善で、必要になったら別 issue にする

全項目が決着した（提案はすべて却下、局所の改善は実施済み）。
